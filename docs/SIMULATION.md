# 경기 시뮬레이션 모델

코드: `com.mlbgame.sim` (Spring 비의존 순수 Java)

## 1. 흐름

```
[능력치 20~80] --RateModel--> [선수별 확률 배열 (캐시)] --GameSimulator--> [GameResult(박스스코어)]
   커리어 DB                     능력치 바뀔 때만 계산                 경기마다
```

1. **RateModel** — 능력치를 타석 결과 9종의 확률로 변환. 선수당 `double[9]` 1개.
   능력치가 변할 때만 다시 계산하고, 평소에는 메모리 캐시를 쓴다.
2. **GameSimulator** — 타석 단위로 경기를 진행하고 박스스코어를 만든다. DB 접근 없음.

## 2. 타석 결과

`삼진, 볼넷, 몸에 맞는 공, 단타, 2루타, 3루타, 홈런, 땅볼 아웃, 뜬공 아웃` (9종, `Outcomes`)

리그 평균 (2024~2025 MLB 근사, 임포터 완성 후 실제 값으로 교체):

| 삼진 | 볼넷 | 사구 | 단타 | 2루타 | 3루타 | 홈런 | 땅볼아웃 | 뜬공아웃 |
|---|---|---|---|---|---|---|---|---|
| .224 | .083 | .011 | .140 | .043 | .004 | .030 | .205 | .260 |

## 3. 능력치 → 확률

- 능력치를 z 점수로 변환: `z = (능력치 - 50) / 10` (20~80 스케일에서 10점 = 1 표준편차)
- 결과별로 `리그평균 × exp(Σ 계수 × z)` 후 합이 1이 되도록 정규화. 인플레이 아웃은 기준 결과(계수 0)이고
  땅볼/뜬공 비율만 성향 능력치로 기운다.
- **계수(`RateCoefficients`)는 실제 2026 기록에서 회귀 추정**: 결과마다 "그 결과 vs 인플레이 아웃" 로지스틱 회귀
  (`log(p_i/p_아웃) = 절편 + Σ 계수·z`)로 모델 구조와 정확히 같은 형태. 손으로 정한 계수는 컨택이 삼진을 줄이면서
  단타도 직접 늘리는 식으로 같은 효과를 두 번 세는 문제가 있어 교체했다. 투수의 단타·2루타·3루타는 "홈런 외 안타" 계수 공유.
  모든 능력치가 50인 선수는 정확히 리그 평균이 된다.
- 투수는 정규화한 뒤 리그 평균으로 나눈 **비율**(`p / 리그평균`)로 저장.
- **효과 배율**(`Spread`): 결과 그룹(삼진 / 볼넷·사구 / 홈런 / 홈런 외 안타)마다 `exp(배율 × Σ 계수 × z)`.
  기본 1. 회귀 계수가 이미 실제 퍼짐을 담고 있으므로 게임 밸런스 조정용 손잡이로만 남겨둔다.

### 타자-투수 대결 (다항 odds ratio, log5 일반화)
```
가중치_i = 타자확률_i × 투수비율_i   (= 타자_i × 투수_i / 리그_i)
```
타석마다 곱셈 9번 + 난수 1개로 결과가 정해진다. `exp`/`log` 없음, 객체 생성 없음.

추가 보정 (모두 곱셈 1번):
- 투타 상성: 유리하면 타자에게 좋은 결과 ×1.04, 불리하면 ×0.96 (스위치 타자는 항상 유리)
- 발휘율: 타자는 좋은 결과에, 투수는 아웃 결과에 곱함 (0.90 ~ 1.05)
- 팀 수비: 인플레이 안타(단타·2루타·3루타)에 곱함

## 4. 경기 규칙 (v1)

| 항목 | 처리 |
|---|---|
| 주자 진루 | 상황(아웃 수, 베이스)과 주자 스피드 기반 확률 |
| 병살 | 무사/1사 + 1루 주자 + 땅볼 → 타자 스피드 기반 확률 |
| 희생플라이 | 2사 전 3루 주자 + 뜬공 아웃 → 주자 스피드 기반 확률 |
| 도루 | 1루 주자(2루 비어 있음) → 시도율은 도루 능력치, 성공률은 스피드 vs 포수 송구 |
| 투수 교체 | 선발: 투구 수 한계, 6실점, 또는 상대 타자 27명(타순 3바퀴) 후 다음 이닝 / 불펜: 1이닝 또는 한계 / 마무리: 9회 이후 1~3점 리드 또는 연장 동점. 4점 차 이상이면 불펜 뒤쪽(추격조)부터 투입 |
| 투구 수 한계 | 스태미나 하나로 통일: `min(105, 15 + (스태미나 - 20) × 1.6)` (50 → 63구, 70 → 95구, 상한 105). 실제 선발은 대개 80~100, 불펜은 20~35 |
| 연장 | 10회부터 2루 주자 배치 (자책점 제외) |
| 야수 선택 | 1루 주자 + 2사 전 땅볼(병살 아님)의 40% → 선행 주자 2루 포스아웃, 타자 1루 |
| 주루사 | 추가 진루 시도 중 2루→홈(단타) 5%, 1루→3루 4%, 1루→홈(2루타) 6% 아웃 |
| 실책 출루 | 인플레이 아웃 중 일정 확률(땅볼 ×1.4, 뜬공 ×0.6, 팀 수비력 반영) → 타자 1루, 모든 주자 1베이스 진루, 비자책 |
| 폭투·포일 | 주자가 있을 때 타석 전 일정 확률로 모든 주자 1베이스 진루 |
| 자책점 | 실책이 없었다면 이닝이 끝났을 시점(아웃 + 실책 ≥ 3) 이후 득점은 비자책 |
| 끝내기 | 홈팀 리드 시 즉시 종료 |
| 기록 | 타자 15종, 투수(아웃·피안타·실점·자책·볼넷·삼진·피홈런·사구·투구 수), 승/패/세이브, 이닝별 점수 |
| 실점 책임 | 주자마다 책임 투수를 기록 → 승계 주자 실점이 정확히 이전 투수에게 |

v2 후보: 대타·대주자, 수비 교체, 고의4구, 번트, 안타 중 실책 추가 진루.

## 5. 성능 설계

- 시뮬 중 **할당 거의 없음**: 상태는 재사용 배열, 경기당 생성 객체는 결과(박스스코어 배열 + 투수 기록 약 8개)뿐.
- 난수: `SplittableRandom` (경기별 seed → 재현 가능, `Random` 보다 빠르고 락 없음).
- `GameSimulator` 는 스레드 안전하지 않음 → 스레드당 1개. 하루 15경기는 단일 스레드로도 충분.
- 측정: `./gradlew benchmark` (경기당 µs, 시즌 2,430경기 소요 시간 출력).

## 6. 능력치 산정 (임포터, `RatingImporter`)

| 능력치 | 근거 (가중치) |
|---|---|
| 컨택 | 삼진율↓ .40, 헛스윙률↓ .40, xBA .20 |
| 파워 | 배럴% .35, 평균 타구속도 .20, 타석당 홈런 .30, 순장타율 .15 |
| 선구안 | 볼넷률 .50, 볼 존 스윙률↓ .50 |
| 타구 질 | 강한 타구% .40, 스윗스팟% .25, xBA .35 |
| 타구 성향 | 땅볼% |
| 스피드 | 스프린트 속도 |
| 주루 | 도루 시도율 .50, 도루 성공률 .20, 스프린트 .30 |
| 제구 | 볼넷률↓ .70, 존 투구율 .30 |
| 피안타 억제 | 피배럴%↓ .35, 허용 타구속도↓ .20, 피홈런율↓ .30, 강한 타구 허용↓ .15 |
| 땅볼 유도 | 땅볼% |
| 구종별 구위 | 같은 구종끼리 비교: 헛스윙률 .45, 구종 run value/100 .35, 구속 .20 |
| 스태미나 | 최근 2시즌 등판당 아웃 → 추정 투구 수 → 위 공식의 역산 |
| 수비 | OAA (포지션 기준), 포수는 프레이밍 .50 + 블로킹 .25 + 팝타임 .25. 다른 포지션은 이동 난이도로 파생 |
| 송구 | 송구 속도 (포수는 2루 송구 속도) |

- 전통 기록은 2024~2026 을 1:2:3 가중. Statcast 는 2026.
- 표본 보정 `z' = (n·z + k·prior) / (n + k)`: 기록이 적은 선수는 평균(50)보다 아래(prior)로 끌린다.
- 50 = 표본이 충분한 선수들의 평균.

## 7. 실제 2026 재현 검증 + 자동 보정 (`SeasonValidator`)

산정한 능력치 + 실제 개막 로스터 + 실제 2026 일정으로 시즌을 반복 시뮬레이션해 실제와 비교하고,
아래 세 가지를 함께 반복 보정해 `mst_league` 에 저장한다 (게임 서버는 이 값을 읽어 쓴다).

| 단계 | 대상 | 목표 |
|---|---|---|
| 0 (1회) | 능력치 → 결과 계수 | 실제 2026 기록 회귀 (능력치가 있는 전체 선수, 20타석 이상) |
| 반복 | 리그 기준값 (50 vs 50 확률) | 선수마다 "실제 출전량 × 시뮬 비율" 합 = 실제 기록 합 (타자·투수 쪽 비율의 기하평균) |
| 반복 | 실책 확률 | 비자책 비율 |
| 반복 | 폭투·포일 확률 | 득점 효율 = 득점 ÷ BaseRuns 기대 득점 |

- 리그 전체 평균에 맞추지 않는 이유: 실제 리그 기록에는 벤치·콜업 선수가 섞여 있지만 시뮬은 개막 주전만 뛴다.
  실제 출전량으로 가중하면 "시뮬에선 주전이지만 실제로는 부상·강등으로 거의 못 뛴 선수"의 영향도 작아진다.
- 검증 지표 "기울기"(실제 기록을 시뮬 기록에 회귀): 1 = 능력치 차이가 실제 기록 차이를 과장·축소 없이 예측.
  선수를 시뮬 쪽(주전 여부)으로 고르므로 "운 좋게 잘해서 많이 뛴 선수만 남는" 선택 편향을 받지 않는다.
- 실제 출전량 가중 평균은 타자·투수 모두 "실제가 더 좋게" 나온다 (잘 풀린 선수가 더 많이 뛰기 때문).
  타자 쪽과 투수 쪽이 동시에 실제보다 좋을 수는 없으므로, 이 차이는 보정할 대상이 아니라 선택 효과다.
- 한계: 부상·휴식·트레이드·콜업·구장 효과 없음.

## 8. 저장 (다음 단계)

- "다음 날" 1회 = 그날 경기 전체 시뮬 → **한 트랜잭션에서 배치 INSERT**
  (경기 요약, 타자/투수 박스스코어) + 시즌 누적 스탯 `INSERT ... ON DUPLICATE KEY UPDATE` 배치.
- 이닝별 점수 같은 작은 배열은 별도 행 대신 경기 행의 컬럼(짧은 문자열/바이너리)으로.

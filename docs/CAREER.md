# 다년 커리어 설계

2026 개막에서 시작해 시즌이 계속 이어지는 커리어. 계약·FA는 단순화하고 성장·노화·은퇴·신인 유입만 둔다.
아래에서 **결정**은 사용자 확정, **제안**은 기본안(확정 전).

## 1. 범위 (결정, 2026-11-02)

| 항목 | 결정 |
|---|---|
| 커리어 형태 | 다년 커리어. 시즌 종료 → 오프시즌 → 다음 시즌 개막으로 계속 진행 |
| 성장·노화 | 포함 |
| 은퇴 | 포함 |
| 신인 유입 (드래프트) | 컴바인·고교/대학 리그 같은 과정은 없음. 신인은 능력치만 생성되고, 스카우트 분석치를 보고 유저가 지명 |
| 해외 선수 (포스팅) | 능력치만 생성. 과거 기록(가상의 해외 리그 성적)은 만들지 않음 |
| 계약·FA | 잔여 연수 + 연봉 + 팀 예산 상한. 세부 조항 없음. 연봉·계약은 자동 산정 (공식 API 에 계약 데이터 없음) |
| 드래프트 규모 | 10라운드 300명 |
| 마이너 | AAA·AA 2단계, 경기도 시뮬한다 (6번) |

## 2. 시즌 흐름

```
개막 ── 정규시즌 162경기 ("다음 날" 반복) ── 포스트시즌 ── 오프시즌 처리 ── 다음 시즌 개막
                                                          │
                                   ┌──────────────────────┴───────────────────────┐
                                   1. 시즌 기록 마감 (누적 기록 확정, 지난 시즌 경기 상세 정리)
                                   2. 은퇴
                                   3. 성장·노화 (나이 +1, 능력치 변화)
                                   4. 계약 만료 → FA 시장
                                   5. 포스팅 선수 등장
                                   6. 드래프트
                                   7. 다음 시즌 일정 생성
```
- 오프시즌 단계는 유저 입력이 필요한 곳(FA 영입, 드래프트 지명)에서 멈추고, 나머지는 한 번에 일괄 처리한다.
- 일정은 2026 실제 일정을 템플릿으로 쓰고, 날짜만 해당 시즌으로 옮긴다 (요일 맞춤).

## 3. 성장·노화 (제안)

- 오프시즌마다 1회 (시즌 중 소폭 변화는 추후 검토).
- 능력치마다 나이 곡선이 다르다. 예: 스피드는 일찍 하락, 선구·제구는 늦게까지 유지·상승, 파워는 20대 후반 정점.
- `변화량 = 나이 곡선(능력치 종류, 나이) + 잠재력 여유분 보정 + 무작위(정규분포)`
- 잠재력(`potential`)은 상한이 아니라 "성장 여지" 신호로 쓴다. 젊고 잠재력이 높을수록 상승 기대치가 크다.
- 곡선 계수는 실제 데이터(연도별 기록의 나이별 변화, aging curve)로 추정한다. 능력치 회귀와 같은 방식.

## 4. 계약·FA 단순화 (결정: 연수 + 연봉 + 팀 예산, 세부는 제안)

- 선수마다 `잔여 계약 연수` + `연봉` 만 둔다. 옵션·옵트아웃·트레이드 거부권 같은 세부 조항은 없음.
- 연봉·잔여 연수는 능력치·나이·데뷔 후 연차(API 의 MLB 데뷔일)로 자동 산정한다.
- 팀 예산은 산정 연봉 합계를 기준으로 구단 규모에 따라 단계화한다.
- 팀 예산 = 구단별 상한 (2026 실제 페이롤 수준).
- 계약이 끝난 선수는 FA. AI 구단은 필요 포지션과 예산 기준으로 영입하고, 유저는 제안을 넣어 수락 여부를 판정받는다.
- 서비스 타임(연봉조정·FA 자격 연수)은 단순 규칙으로: 데뷔 후 N년간 최저 연봉, 이후 FA.

## 5. 신인·포스팅 (결정 + 제안)

- **결정**: 10라운드 300명. 생성된 능력치(진짜 값)는 숨기고, 유저는 스카우트 수준에 따른 추정 범위만 본다 (기존 스카우트 시스템 그대로).
- **제안**:
  - 지명 순서: 정규시즌 역순위.
  - AI 구단은 자기 스카우트 추정치로 지명한다. 유저 스카우트 수준이 높을수록 "숨은 진주"를 먼저 잡을 수 있다.
  - 포스팅: 매 오프시즌 소수(예: 5~10명) 생성. 신인보다 완성도가 높고 나이가 많음 (24~30세, 즉시 전력 위주).
  - 신인 능력치 분포는 실제 드래프티의 MLB 도달률·도달 시 능력치 분포를 참고해 정한다.

## 6. 마이너 리그 (결정: AAA·AA 2단계, 경기 시뮬 포함)

- **선수 (결정)**: 실제 2026 개막 AAA·AA 로스터를 임포트한다 (MLB Stats API sportId 11/12, 모기업 연결 포함).
  능력치는 마이너 기록을 메이저 환산치로 바꿔 산정하고 (AA 는 Statcast 없음),
  기록이 부족해 산정이 어려운 선수는 레벨·나이 기반 분포에서 무작위로 배분한다.
- **능력치 산정 (구현)**:
  1. 레벨 환산 계수: 같은 시즌에 두 레벨(AAA·MLB / AA·AAA)을 함께 뛴 선수 짝으로 결과별 비율 추정
     (두 표본의 조화평균 가중). AA→MLB = AA→AAA × AAA→MLB.
     아래 레벨 기록은 결과별 안정화 표본만큼 레벨 평균 쪽으로 회귀시켜 쓴다 — 콜업은 "실력 + 운"으로 결정되므로
     원 기록으로 나누면 타자는 볼넷·홈런 계수가 과하게 낮고 투수는 과하게 높아지는 선택 편향이 생긴다. `mst_level_factor` 에 저장 (마이너 경기 시뮬 기준값에도 사용).
  2. 최근 3시즌(3:2:1) 마이너 기록을 MLB 환산 기록으로 바꿔 MLB 기록과 합침.
  3. 시뮬레이터 계수로 능력치 역산 (MAP: 기록 가능도 + 레벨 평균 사전값). 레벨 평균은 표본 큰 선수들의 1차 역산값.
     땅볼 성향은 땅볼 비율, 스피드 사전값에는 도루 시도율을 반영. 수비·송구는 기록이 없어 45 ± 무작위.
  4. 환산 표본이 60 미만이면 레벨 분포에서 무작위 (선수 ID 시드라 재실행해도 같음).
  - MLB 가중 표본 150 이상 선수는 Statcast 기반 능력치 유지. `mst_player_rating.source` = 0/1/2 로 구분.
- 마이너 경기도 메이저와 같은 엔진으로 시뮬한다. 경기당 약 8µs 라 CPU 비용은 무시할 수준이다.
  부담은 **저장**에서 생기므로 저장 방식을 메이저와 다르게 둔다.
- **제안 (최적화)**:
  - 마이너 경기는 박스스코어를 저장하지 않는다. 순위(팀 승패)와 선수 시즌 누적 기록만 저장.
  - 누적 기록은 메이저와 같은 "하루치를 메모리에서 합산 → 한 번에 배치 업서트" 방식.
  - 마이너 일정은 실제 일정이 아니라 단순 생성 (같은 레벨 30팀 리그, 레벨별 경기 수).
  - 마이너 리그 기준값은 레벨마다 메이저보다 낮은 상대 수준으로 둔다 (상위 레벨일수록 메이저에 가까움).

## 7. 저장 용량 (커리어가 길어질 때)

- 시즌당 경기 상세(`c_game` 박스스코어 약 500B × 2,430) ≈ 1.2MB/커리어/시즌. 누적 기록(`c_player_season`)은 작다.
- **제안**: 지난 시즌 경기 상세는 오프시즌에 삭제하거나 최근 N시즌만 보관하고, 누적 기록과 포스트시즌 기록은 영구 보관.
- 선수 수가 계속 늘지 않도록 은퇴·방출이 신인 유입과 균형을 이루게 한다 (커리어당 선수 수 상한 관리).

## 8. 커리어 생성 (구현: `career` 패키지)

```
MasterData (마스터 메모리 캐시, 최초 1회 로드)
  → 선수마다 RatingSampler (절단 정규분포) + 숨김 성격 + ContractModel (계약)   ← 트랜잭션 밖, 메모리
  → 트랜잭션: 슬롯 잠금 확인 → career INSERT → c_player 배치 INSERT (약 2,650행) → c_team 30행
```
- 선수별 난수 = `커리어 seed ^ (선수 ID × 상수)` → 같은 커리어는 언제 다시 만들어도 같고, 선수 순서와 무관.
- σ = 3 × min(표본 × 나이 × 항목 배율, 1.6), ±2σ 재추첨.
  - 표본: MLB 기록 기반은 2026 표본 500 미만일수록 최대 1.6배, 마이너 환산 1.4, 무작위 1.6
  - 나이: 22세 이하 1.3 / 25세 이하 1.15 / 30세 이하 1.0 / 34세 이하 0.9 / 그 이상 0.85
  - 항목: 스피드 0.6, 땅볼 성향·스태미나 0.8, 구위 0.9, 수비·프레이밍·블로킹·내구성 1.3, 잠재력 1.5. 구사율은 고정
- 숨김 성격(적응력·멘탈 안정성·프로의식): 50 ± 10 (±2σ)
- 개막 배치: 26인 → MLB / 40인 + AAA·AA 로스터 → 해당 레벨 / 40인 미배정 → MLB 기록 기반이면 부상자 명단(10~60일), 아니면 AA /
  마이너 계약 → 해당 레벨
- 계약 (`ContractModel`, 연봉 단위 천 달러, 모두 튜닝 상수):
  - 마이너 계약: 연봉 7.5만 달러 고정 (예산·연봉 합계 제외), 1~3년 (드래프트 6년)
  - 서비스 0~2년: 최저연봉 78만 달러 고정 (연차 무관), 보유 연수 = 6 - 서비스
  - 40인에 오른 마이너 계약 선수는 오프시즌에 MLB 계약(연봉조정 전)으로 전환
  - 서비스 3~5년: 시장가치 × 35/55/75%
  - 서비스 6년 이상: 시장가치, 잔여 1~6년 (30세 이하·가치 60 이상이면 2~6년)
  - 시장가치 = 최저연봉 + 단가 × 초과가치, 최대 6,500만. 초과가치 = max(0, 가치 - 45) + 슈퍼스타 가산 0.1 × max(0, 가치 - 65)²
    (가치 75 +10, 80 +22.5: 최상위만 가파르게). 34세 이상 ×0.75, 37세 이상 ×0.5
  - 단가는 "40인 연봉 합계 = 실제 리그 총액 48억 달러" 가 되도록 마스터 선수 전체로 계산 (상수로 정하지 않음)
  - 서비스 연차 = 2026 이전 MLB 출전 시즌 수 (실제 서비스 일수의 근사)
- 팀 예산 (커리어 시작) = max(7,000만, 40인 연봉 합계 × 1.10). 이후 매 오프시즌 아래 "구단 예산" 규칙으로 다시 정함

### 구단 예산 (구현: `offseason.LeagueBudget`, 1단계 결과 요약에 표시, 7단계에서 저장)
- 예산 = 리그 시장 규모 L (30구단 예산 합) × 구단 비율 r (리그 평균 = 1.0) / 30.
- L 은 매년 +2~6% (커리어 seed + 시즌으로 결정, 하락 없음). 연봉 시세(4단계)도 L / 1.1 을 목표로 맞춰 시장과 함께 오른다.
- r 하한 0.40, 상한 2.50 (실제 개막 연봉: 최하 약 0.4배, 최고 약 2.2배).
- 기준 비율 = (시장 규모 지수 + 커리어 시작 예산 비율) / 2, 첫 오프시즌에 `c_team.base_share` 로 저장.
  시장 규모 지수: NYY·LAD 1.75, NYM 1.45, BOS 1.40, CHC 1.35 … TB·MIA·ATH 0.65 (연고지·매출 규모 근사).
- 성적: 승패 차 1승당 +0.3% / -0.4% (리빌딩 감축이 더 빠름). 포스트시즌 진출 +2%, 시리즈 승리 WC 1 / DS 1.5 / CS 2 / WS 2.5% (우승 최대 +9%).
- 구간 (사치세 기준선 약 1.5배):

| 구간 (r) | 플러스 요인 | 마이너스 요인 | 회귀 (매년) |
|---|---|---|---|
| ~1.5 사치세 아래 | ×1.0 | 그대로 | 기준 비율 쪽 10% |
| 1.5~1.9 사치세 구간 | ×0.6 | 그대로 | min(기준, 1.5) 쪽 20% |
| 1.9~2.5 최고 구간 | ×0.3 | 그대로 | min(기준, 1.5) 쪽 30% |

- 적용 → 합 30 으로 맞춤 → 상·하한 자르기를 반복. 장기 결과(30년 모의): 빅마켓 왕조 약 1.9배, 평범한 빅마켓 약 1.5배,
  스몰마켓 왕조 약 8년에 걸쳐 1.5배까지, 평범한 스몰마켓 0.6~0.8배.
- 이미 맺은 연봉이 줄어든 예산을 넘어도 강제 정리는 없음. 그해 재계약·FA 영입만 막힌다.
- 벤치마크: `--spring.profiles.active=local,career-bench` (생성·삭제 반복, 샘플링·배치·연봉 점검 출력)

## 9. "다음 날" (구현: `season` 패키지)

```
CareerRuntimeCache (Caffeine, 최대 32개·30분 미사용 시 내림)
  └ CareerRuntime: 레벨(MLB/AAA/AA) × 30팀 자동 구성(선발별 SimTeam), 순위, 선수→구단
NextDayService.advance
  1. 메모리만으로 하루치 시뮬: MLB(mst_schedule) + AAA·AA(MinorSchedule, 계산식 일정)   DB 읽기 0
  2. DayBatch 에 하루치 기록 합산 (선수·레벨당 1행)
  3. 한 트랜잭션: career UPDATE(version 확인) → c_game 배치 → 순위 upsert → c_bat_season/c_pit_season 가산 upsert
  실패 시 캐시에서 내림 → 다음 요청이 DB 기준으로 다시 만든다
```
- 로테이션 순번 = 치른 경기 수 % 선발 인원 (저장 없이 복원).
- 경기 seed = 커리어 seed + 시즌 + 레벨 + 경기 키 → 같은 상태면 같은 결과.
- 마이너 일정: 30팀 매일 15경기, 월요일 휴식, 3연전 라운드로빈. AAA 는 MLB 개막+2일~MLB 종료일, AA 는 개막+8일~종료-7일.
- 마이너 리그 환경 = MLB 비율 ÷ √(타자 환산 계수 × 투수 환산 계수) (상대 수준 효과가 서로 상쇄 → 순수 리그 환경).
- 마이너 경기는 박스스코어를 저장하지 않는다 (순위·시즌 누적만).
- 정규시즌 마지막 날을 치르면 단계 = 포스트시즌(2).

### 포스트시즌 (구현: `Postseason`, `Series`)
- 2022~ MLB 12팀 방식. 리그별 시드: 지구 우승 3팀(1~3, 성적순) + 와일드카드 3팀(4~6). 동률은 득실차 → 팀 ID.
- 와일드카드 3전(3 vs 6, 4 vs 5, 상위 시드 홈 3경기) → 디비전 5전(1 vs 4·5 승자, 2 vs 3·6 승자, 2-2-1)
  → 챔피언십 7전(2-3-2, 상위 시드 홈) → 월드시리즈 7전(정규시즌 성적 좋은 팀 홈).
- 정규시즌 다음 날 하루 휴식 후 와일드카드 시작, 라운드 사이 하루 휴식, 시리즈 중 홈이 바뀌면 이동일 하루.
- 상위 4선발 로테이션(포스트시즌 경기 수 % 4), 휴식 교체 없음, 부상·불펜 피로 규칙은 그대로.
- 저장: 시리즈 `c_series`, 경기 `c_game`(game_no = 10000 + 시리즈 × 10 + 경기 순번, 박스스코어 포함),
  기록은 `c_bat_season`/`c_pit_season` 레벨 3 (정규시즌과 분리).
- 시드는 저장하지 않는다: 정규시즌 순위가 고정이라 다음 라운드를 만들 때 다시 계산.
- 월드시리즈가 끝나면 단계 = 오프시즌(3).

### 오프시즌 (구현: `offseason` 패키지, `OffseasonService.runStage` / 남은 단계 전부 `run`)
7단계로 나눠 "다음 단계" 버튼 1회 = 1단계. 단계마다 전 선수를 읽어 메모리에서 그 단계만 처리하고 한 트랜잭션으로 쓴다
(c_player 전체 upsert + 신규 c_person + `c_offseason` 끝낸 단계·연봉 단가·결과 요약 누적). 중간에 멈춰도 다음 단계부터 이어짐.

| 단계 | 아래 표 순서 |
|---|---|
| 1 시즌 마감·드래프트 추첨 | 1 + 드래프트 순서 확정 (`c_draft_pick` 300장) |
| 2 은퇴 / 3 성장·노화 / 4 연봉 재산정 | 2 / 3 / 4 |
| 5 FA 시장 개장 | 내 팀 계약 결정 반영 + 5 포스팅 + 가치 46+ FA 를 `c_fa_player` 에 등록 (4단계 연봉 단가 사용) |
| (FA 라운드 1~6) | FA 화면에서 라운드마다 진행 (`FaService`), 계약 선수 행만 바로 저장 |
| 6 FA 시장 마감 | 남은 라운드 AI 진행 → 6 의 마이너 계약 |
| 7 드래프트 | 7 (1단계에서 정한 순서, 지명 선수를 `c_draft_pick` 에 기록) |
| 8 개막 로스터·새 시즌 | 8~11 |

유저 결정:
- 드래프트 지명 (구현, `DraftService` · `/careers/{id}/draft`): 5단계가 끝나면 대시보드가 "드래프트 화면"으로 안내.
  후보 300명은 저장하지 않고 seed + 시즌 + 첫 신규 ID 로 6단계와 똑같이 다시 생성. 지명은 `c_draft_pick.player_id` 에
  한 장씩 기록 ("내 차례까지 진행" = AI 구단이 내 지명권 직전까지, 내 지명 후 다음 내 차례 직전까지 AI 자동).
  내 지명권을 다 쓰면 "드래프트 마감" = 6단계 처리 (기록된 지명 그대로 + 빈 지명권 AI, 지명 선수 생성).
  후보 능력치·잠재력은 스카우트 범위, 순위는 범위 중심(추정값)으로 AI 와 같은 공식. 같은 선수 중복 지명은 유니크 키로 차단.
- 재계약·텐더 (구현, `ContractService` · `/careers/{id}/contracts`, 표 `c_contract_decision`):
  1단계에서 내 팀은 바로 방출하지 않고 대상 등록 — FA 자격(MLB 계약 만료·서비스 6년 도달) / 연봉조정(서비스 3~5년).
  마이너 계약 만료는 자동. 4단계(연봉 재산정)가 끝나면 대시보드가 "계약 결정 화면"으로 안내.
  재계약 = 다음 시즌 시장가치 연봉 × 1~15년 (게임 재미용, 단 45세 시즌을 넘는 기간 불가, 연봉은 연수와 무관하게 고정), 포기 = FA 시장으로.
  텐더 = 4단계 조정 연봉으로 보유, 논텐더 = 방출. 재계약은 다음 시즌 예산(구단 예산 규칙) 안에서만.
  5단계 시작 때 반영 (`OffseasonRules.applyDecisions`). 결정하지 않은 선수는 AI 기본값 (FA 자격 포기, 가치 45+ 텐더).
- FA 입찰 (구현, `FaMarket` 규칙 · `FaService` · `/careers/{id}/fa`, 표 `c_fa_player`·`c_fa_offer`): 6라운드.
  - 선수가 먼저 요구액(연봉 × 원하는 연수)을 부른다: 시장가치 × (1.0 + 0.3 × clamp((가치-55)/20, 0, 1) ± 5%).
    숨김 최저선 = 시장가치 × 0.85~1.00. 원하는 연수: 27세 이하·가치 65+ 10~15년, 30세 이하·가치 60+ 6~9년, 33세 이하 2~4년, 그 외 1~2년.
  - 제안 점수 = 연봉 × 연수 보정 (원하는 연수보다 1년 짧을 때마다 -4%, 길면 +1%/년, 최소 0.6). 유저 연수 1~15년 (45세 시즌까지).
  - 라운드 판정: 요구액 × 1.15 이상 즉시 계약 / 경쟁(요구액 90%+ 제안 2곳 이상)이면 버티기(가치 65+ 2~4라운드) 뒤 요구액 이상에 계약,
    아니면 요구액 +5~10% / 경쟁 없으면 요구액 이상에 계약, 아니면 요구액 -5% (최저선까지) / 6라운드는 최저선 이상이면 계약.
  - AI 상한 = 시장가치 × (0.95 + 0.06×부족(최대 5) + 0.015×개선폭(최대 20) + 0.2×무작위), 예산 여유 안. 밀리면 최고 제안 +5% 또는 요구액까지.
  - 유저에게는 요구액·관심 구단 수·반응 문구만 (다른 구단 금액 비공개, 계약 성사 시 공개). 제안 합계 + 확정 연봉 ≤ 다음 시즌 예산.
- "남은 단계 한 번에"·시즌 일괄 진행 버튼은 테스트용 임시 기능 (유저 결정 화면 완성 후 제거). 내 드래프트 지명·계약 결정도 AI 가 대신.

드래프트 순서 (`DraftLottery`, 2023 노사협약 근사):
- 1라운드 1~6순위: 포스트시즌 미진출 18구단 추첨. 성적 역순 확률 16.5% ×3, 13.25, 10, 7.5, 5.5, 3.9, 2.7, 1.8, 1.4, 1.1,
  0.9, 0.8, 0.6, 0.4, 0.2, 0.2 — 한 장 뽑을 때마다 남은 구단끼리 비율 유지. 최저 성적 구단도 최악 7순위.

- 나이 곡선 (`AgingCurves`): 마스터 DB 의 MLB 연도별 기록에서 같은 선수 연속 두 시즌의 지표 변화 (delta method).
  평균 회귀 편향 제거: 앞 시즌 기록만 안정화 표본(삼진 60, 볼넷 120, ISO 160, 인플레이 안타 1200, 도루 200 / 투수 삼진 70,
  볼넷 170, 피홈런 1300)만큼 그 나이 평균 쪽으로 당겨 "앞 시즌 실력"으로 보고 뒤 시즌 기록과 비교 (운 좋은 해에 짝이 지어지는 문제).
  변화를 실력 표준편차 단위(관측 분산 - 표본 분산)로 바꿔 ×10 = 능력치 변화. 나이별 조화평균 가중, ±2세 삼각 평활, 1년 ±5 제한.
  지표: 삼진율→컨택, 볼넷률→선구, ISO→파워, 인플레이 안타율→타구질, 도루 시도율→스피드(수비 범위 0.7배, 송구 0.5배),
  투수 삼진율→구위, 볼넷률→제구, 피홈런율→장타억제. 한계: 은퇴 선수 기록이 없어 생존 편향 가능.
- 시즌 달력 (`SeasonCalendar`): 2026 일정 템플릿 + (364 × 경과 연수 + 7 × round(1.25 × 경과 / 7))일. 요일 유지, 개막 3월 하순.
- 아직 없음: 룰5 드래프트, 지명권 트레이드·AI 끼리 트레이드, 국제 아마추어 계약 (유저 제안 선수 트레이드는 구현: ARCHITECTURE 9번). (40인 상한은 시즌 중·커리어 적재 시 유지, `DayRules.trimFortyMan`)
- 시즌 중 운영 (`DayRules`, AI 구단 공통, 경기 seed 에서 파생한 별도 난수):
  - 휴식: 경기마다 포수 22% / 야수 10% / 지명타자 8% 확률로 벤치 선수(같은 포지션 가능, 공격력 순)와 교체
  - 플래툰: 상대 선발과 같은 손 타자(스위치 제외)는 반대 손 벤치 타자 중 공격력 5 이내인 선수로 교체
  - 불펜 피로 (`Fatigue`, 메모리만, 최근 8일 등판 비트마스크): 어제 20구 이상 또는 연투 후 휴식, 그제 40구 이상 휴식,
    최근 6일 중 3번 등판하면 휴식, 더블헤더 재등판 불가.
    캐시를 다시 만들 때는 최근 3일 MLB 박스스코어의 투구 수로 복원
  - 부상: 출전 1경기당 타자 0.85% / 선발 3.5% / 구원 1.8% × exp(-0.35 × 내구성 z) → 팀당 시즌 약 30건.
    기간 10일 + 로그정규(중앙 약 22일), 투수 ×1.3, 최대 180일. MLB 부상은 부상자 명단(상태 3)
  - MLB 부상 → 같은 구단 AAA(없으면 AA)에서 같은 유형 콜업 (선발 부상엔 선발 자원, 야수는 같은 포지션 우선).
    복귀 → 같은 유형 MLB 최하위 강등
  - 매일 산하 팀 인원 재조정 (유형별 최소 AAA 11 / AA 타자 10·투수 11): AA 가 모자라면 AAA 여유분(마이너 계약 우선)을
    내리고, AAA 가 모자라면 AA 최고 선수를 올림
  - 선발 투구 수 상한 105구 (스태미나 76 이상 동일)
  - 구단 산하 인원이 재조정 후에도 모자라면 대체 선수 영입 (`Filler`): 레벨 대체 수준 능력치(AAA 약 41, AA 약 38),
    23~28세, 마이너 1년 계약. 신상은 `c_person`(ID 10억부터, 드래프트·포스팅 선수도 같은 테이블 사용 예정)
  - 매주 월요일: 40인 AAA 선수가 같은 유형 MLB 최하위보다 6 이상 좋으면 유형별 팀당 1명 교체
  - 인원 부족으로 팀을 구성할 수 없으면 이전 구성을 유지 (진행을 막지 않음, 벤치마크에 횟수 표시)
  - 선수 조회는 (레벨, 구단) 색인으로 (전체 2,650명 순회 없음)
  - 저장: 상태가 바뀐 선수만 c_player UPDATE (같은 트랜잭션)
- 아직 없음: 40인 명단 상한, 유저 라인업 지정, 시즌 중 트레이드.
- 벤치마크: `--spring.profiles.active=local,season-bench` (정규시즌 전체 진행, 하루 처리 시간·저장량·레벨별 리그 기록)

## 10. 처음에 미리 반영한 것 (구현됨)

커리어 생성과 "다음 날" 서비스를 만들 때 다음을 전제로 한다.
- 일정은 시즌 템플릿 + 커리어 시즌 변환 방식 (`mst_schedule` 은 템플릿 역할).
- 커리어 선수는 "현재 능력치"와 성장 관련 숨은 값(잠재력 등)을 분리해 저장.
- 커리어 생성 시 계약(잔여 연수·연봉)도 함께 생성.
- "다음 날" 흐름에 시즌 종료 → 포스트시즌 → 오프시즌 단계 전환 자리를 둔다 (`career` 의 단계 상태값).
